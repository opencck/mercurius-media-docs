# BRIEF — mercurius-media-docs

Небольшой HTTP-сервис на Python для документов. Он извлекает текст из docx, pptx, xlsx, odt, PDF и RTF и собирает
новые docx, xlsx и pptx по описанию в JSON. С модулем агент читает присланные документы и делает документы по
просьбе. Без модуля документы только сохраняются, а агент говорит, как включить модуль.

## Назначение и границы

Сервис делает:

- `extract` — текст файла не длиннее `limit` символов; вид определяется по расширению в `name`;
- `build` — файл `docx`, `xlsx` или `pptx` из описания: заголовки, абзацы, списки, таблицы, листы, слайды, заметки
  докладчика, формулы в ячейках `xlsx`.

Остаётся в приложении (`src/Infrastructure/Media/DocsService.php`, `src/App/Agent/Media/AttachmentIntake.php`,
`src/App/Agent/Tool/Files/DocumentsTool.php`, `src/App/Agent/Tool/Files/MediaTool.php`):

- когда читать документ (сразу при получении или `media extract` с `offset`), сколько текста брать (`MEDIA_TEXT_LIMIT`);
- куда положить новый файл — в песочницу участника (инструмент `documents`);
- рамка недоверенных данных и маскировка секретов в извлечённом тексте.

Модуль ничего не хранит: файл пишется во временную папку и удаляется после разбора.

## Устройство

| Путь / файл | Что делает |
|---|---|
| `GET /health` | `{"status":"ok","module":"media-docs"}`, без токена |
| `POST /extract?name=a.docx&limit=N` | файл в теле; `{"text": "..."}`; `limit` по умолчанию 20 000 |
| `POST /build` | описание в JSON; готовый файл с MIME своего вида |
| `media_docs/server.py` | HTTP на `ThreadingHTTPServer`: токен, предел тела, дочерний процесс для разбора |
| `media_docs/extract.py` | чтение по видам: python-docx, python-pptx, openpyxl (`read_only`), `zipfile` + ElementTree для ODT, `pdftotext` для PDF, регулярные выражения для RTF |
| `media_docs/build.py` | сборка документов и проверка описания (`BadSpec`) |
| `check.sh` | тесты и линтер |

Ответы с ошибкой: `401` — нет или неверен токен, `400` — пустое тело, `413` — тело больше предела, `415` — такой вид
не читается, `422` — файл не читается или описание не складывается в документ (причина до 300 символов), `500` — без
подробностей.

## Безопасность и пределы

- Вход — `Authorization: Bearer <MEDIA_DOCS_TOKEN>`, сравнение `hmac.compare_digest`; токен короче 16 символов —
  сервис не стартует (код 78).
- Тело больше `MEDIA_DOCS_MAX_MB` (по умолчанию 25, допустимо 1–500) отклоняется по `content-length`, не читаясь.
- Каждый файл разбирается в дочернем процессе: память — 768 МБ (`RLIMIT_AS`), процессорное время — 60 с, общее —
  `MEDIA_DOCS_TIMEOUT` (по умолчанию 30 с, допустимо 5–600). Враждебный файл ломает только этот процесс.
- `pdftotext` — со своим пределом 25 с.
- ODT: `content.xml` больше 20 МБ в распакованном виде не читается; XML с `DOCTYPE` или `ENTITY` отклоняется. RTF
  читается не больше 20 МБ.
- Пределы описания `build`: 2000 блоков, 200 слайдов, 50 листов, 20 000 строк, 200 столбцов, 20 000 символов в тексте.
- Журнал запросов выключен: имена файлов в логи не попадают.
- Образ: пользователь `docs` (uid 10041). Compose: сеть `internal`, `read_only`, `tmpfs /tmp` 256 МБ, `mem_limit: 1g`,
  `pids_limit: 64`, `no-new-privileges`. Порт наружу не публикуется.

## Решения

- Разбор документов вынесен из песочницы и из процесса приложения: библиотеки документов не лежат в песочнице, а
  недоверенный файл не разбирается рядом с данными ядра.
- Дочерний процесс на каждый файл: zip-бомба или огромный XML не роняют сервер.
- Описание документа — простой JSON, а не код: агент говорит, что положить, модуль делает файл.
- Ячейка `xlsx`, начинающаяся с `=`, — формула: таблицы со счётом без кода у агента.
- `xlsx` читается с `data_only=True`: агент видит значения, а не формулы.
- Только стандартный `http.server` и три библиотеки с закреплёнными версиями: мало зависимостей.

## Проверки

- `sh check.sh` — `python3 -m unittest discover -s tests` и `ruff check media_docs tests`. Зависимости разработки —
  `requirements-dev.txt` (в том числе `ruff`).
- CI (`.github/workflows/ci.yml`): одна задача, Python 3.12, ставит `poppler-utils`, затем `pip install` и
  `sh check.sh`; изменения только в `*.md` CI не запускают.

## Связь с Меркурием

- Профиль compose — `media-docs`: добавить в `COMPOSE_PROFILES`.
- `.env`: `MEDIA_DOCS_TOKEN` (пусто — модуля нет, документы только сохраняются), `MEDIA_DOCS_URL` (по умолчанию
  `http://media-docs:8092`), `MEDIA_TEXT_LIMIT` — сколько символов текста идёт в сообщение.
- `ServiceModules` спрашивает `/health` при старте и раз в минуту; инструмент `documents` предлагается, пока сервис
  отвечает.
